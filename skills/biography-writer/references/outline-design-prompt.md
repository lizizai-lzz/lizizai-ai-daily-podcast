# 大纲设计 Prompt

本文件是 biography-writer 阶段 3 的执行细则。读取母文 `10_source.md` 后，按以下指令设计传记大纲。

## 一、设计原则

1. **拒绝简历扩写**：大纲不是履历表的扩写版。如果一章只是"出生→上学→毕业→工作"，必然沦为流水账。
2. **以认知转折为骨**：每章必须承载一个**对人物的新理解**或**人物认知的一次跃迁**，而非时间段。
3. **张力优先于完整**：宁可舍弃某些年份的完整覆盖，也要保住关键节点的深度展开。
4. **类型决定骨架**：不同人物类型适用不同的叙事骨架，不可一刀切。

## 二、人物类型识别

读取母文后，先用以下规则判定类型：

| 信号 | 类型 |
|------|------|
| 主要成就是产品/公司、媒体语境多为"创始人/CEO/产品"、争议多围绕商业决策 | **科技/商业人物** |
| 主要成就是论文/理论/发现、机构是大学或研究院、争议多围绕学术观点 | **学者/科学家** |
| 主要成就是作品（书/电影/音乐/游戏）、媒体多谈"创作观"和"风格" | **艺术家/创作者** |
| 上述都不典型 | **其他**（默认编年体+转折点混合） |

## 三、按类型选择骨架

### 3.1 科技/商业人物 → 产品/公司交织式

骨架：以**关键产品决策或公司里程碑**为锚点，穿插个人状态。

章节命名示例：
- 「从 Y Combinator 到 OpenAI：一个连续创业者的转身」
- 「ChatGPT 之前：被低估的八年」
- 「董事会 72 小时：Sam 的权力过山车」

每章内部结构：
1. 产品/决策的背景场景（1-2 段）
2. 关键选择与博弈（核心篇幅）
3. 个人状态与公开言论（穿插）
4. 这一节点对人物形象的重塑（章尾落点）

**禁忌**：不要按"童年→学生→创业→成功→现在"线性铺排。

### 3.2 学者/科学家 → 学术里程碑式

骨架：以**关键论文/发现/理论突破**为锚点。

章节命名示例：
- 「反向传播之前：Hinton 的固执二十年」
- 「AlexNet：七天改变一切」
- 「从 Toronto 到 Google：学术与工业的拉扯」

每章内部结构：
1. 当时学术界的共识（设定反派/常规）
2. 人物的异见与坚持
3. 突破时刻的具体场景
4. 该突破对学界/工业界的后续影响

**禁忌**：不要按学位时间线或论文目录扩写。

### 3.3 艺术家/创作者 → 作品序列式

骨架：以**代表作品**为锚点，每部作品对应一章或一节。

章节命名示例：
- 「《xxx》：第一部被看见的作品」
- 「转折之作：xxx」
- 「晚期风格：xxx」

每章内部结构：
1. 创作时的生活状态与时代背景
2. 作品的核心创作决策（为何这样写/拍/画）
3. 公开言论中对该作品的自我评价
4. 作品的反响与作者后续的回望

**禁忌**：不要把作品按出版时间排成清单。

### 3.4 其他 → 编年体+转折点混合

按时间推进，但每章必须有一个**转折点**作为锚，而非年份本身。

## 四、章节结构（统一要求）

无论选哪种骨架，最终产出必须包含：

1. **章节总数**：6-8 章（不含开篇钩子与尾声）。
2. **开篇钩子**：单独一节，150-250 字，用一个**场景瞬间**或**反常识判断**切入，禁止用"X 是一位著名的 Y"开头。
3. **正文章节**：6-8 章，每章 400-800 字。
4. **收束章**：1 章，300-500 字。不写"评价遗产"的陈词，而用一个**具体的、可触摸的**结尾场景或一句人物自己的话收束。

## 五、单章设计模板

每章在大纲文档中按以下模板填写：

```markdown
## 第 X 章：{章节标题}

- **覆盖时间**：YYYY-YYYY（或"无明确时间，聚焦某事件"）
- **本章锚点**：{一句话说明这章为什么存在 / 读者读完应该获得什么新认知}
- **核心事件**：
  1. ...
  2. ...
  3. ...
- **关键素材**（来自母文）：
  - 事件：[来源](url)
  - 公开言论："..." — 来自 [Twitter/访谈](url)
  - 争议视角：...
- **本章落点**（章尾要落在什么感受/认知上）：
- **预计字数**：XXX 字
```

## 六、字数预算

- 总字数目标：3000-4000 字（终稿，去 AI 味后）。
- 初稿可以略多 10-15%，去 AI 味时会自然收紧。
- 分配原则：
  - 开篇钩子：200-300 字
  - 每章正文：按重要性 400-800 字，**关键转折章给足篇幅**，过渡章收紧。
  - 收束章：300-500 字。
- 在大纲文档末尾给出**字数预算表**：

| 章节 | 预算字数 |
|------|---------|
| 开篇 | 250 |
| 第 1 章 | 600 |
| ... | ... |
| 收束 | 400 |
| **合计** | 3600 |

## 七、自我审查清单

输出大纲前，逐条检查：

- [ ] 每章都承载一个认知转折，不是时间段。
- [ ] 开篇钩子是一个具体场景或反常识判断，不是身份介绍。
- [ ] 至少 2 章触及争议或失败，不是单一光环叙事。
- [ ] 每章都引用了至少 1 条母文中的具体素材。
- [ ] 章节字数合计落在 3000-4000 区间。
- [ ] 收束章不用"综上所述""纵观一生"这类话。

不通过的项目回到第三步重新调整。

## 八、与用户的交互

大纲完成后：

1. 在对话中**完整展示**大纲（章节标题 + 每章锚点）。
2. 询问用户：
   - 是否同意当前骨架选择？
   - 是否需要调整章节顺序或重点？
   - 是否要补充某个母文中没有但你希望写入的视角？
3. 用户确认后，将大纲写入 `20_outline.md`，进入阶段 4。
4. 用户要求重做时，把当前版本备份为 `20_outline_v{n}.md`，重新生成。
