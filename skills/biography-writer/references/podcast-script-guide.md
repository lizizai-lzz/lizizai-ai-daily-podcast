# 传记 → 单人播客脚本改写指南

> ⚠️ **废弃声明**：本文件描述的"单人旁白"模式已废弃，biography-writer 阶段 6 与 lizz-biography-podcast **仅支持访谈式（VO/SOT）**，不再产出纯旁白正片。本文件**仅保留"情感标签规范"部分（第三、四节）作为 VO/片头片尾的情感标签参考**，其余单人脚本改写流程不得再执行。

本文件是 biography-writer **可选阶段 6** 的执行细则。把 `40_final.md`（去 AI 味后的传记终稿）改写为单人播客脚本，并调用火山引擎 Seed-TTS 合成 MP3。

## 一、核心原则

人物传记播客的核心基调是**娓娓道来**，不是新闻播报，不是带货解说。读者是戴耳机在通勤路上、做家务时、睡前听的人，他们要的是**一个声音在给他们讲一个人的故事**。

三条不可违反的底线：

1. **原文保真**：保留 95%+ 原文内容。只做必要的播客适配（去标题、去分隔符、合并过碎的短段）。明显的事实错误可以改，修辞上的微调要克制。
2. **不加戏**：不要把传记语言翻译成"主播腔"。不要加"朋友们""大家好""欢迎收听"。不要在段间加过渡旁白。
3. **情感标签克制**：这是和 AI 日报播客最大的区别——日报可以欢快、可以一针见血，传记不行。传记要像深夜电台，像在念一本好书。

## 二、改写操作清单

### 2.1 必删项

- 所有 `##` / `###` 章节标题（播客没有目录）
- 所有 `---` 水平分隔符
- 文末的"参考资料""素材来源"列表（如有）
- 作者按、脚注、编辑标注

### 2.2 可调整项（谨慎）

- **过长的段落**（>400 字）：可以在自然语义停顿处断成两段，便于 TTS 呼吸感。
- **明显的排版碎片**：连续多个 1-2 行的短段，可以合并为一段，避免 TTS 节奏过碎。
- **括号内的来源标注**（如"（来源：纽约客）"）：移除，声音里不需要。
- **明显的事实笔误**：直接改。

### 2.3 禁止项

- 禁止改写句式让它"更适合朗读"——原文已经是去 AI 味后的成品。
- 禁止增加过渡句（"接下来我们看看…"、"让我们把时间拨到…"）。
- 禁止增加第二人称互动（"你可能会想…"、"你听出来了吗"）。
- 禁止增加章节预告或回顾。

## 三、情感标签规范

### 3.1 格式

火山引擎 Seed-TTS 的情感标签格式：

```
[情感描述] 正文段落内容...
```

标签**独占行首**，紧跟段落第一字，不加空格。每段开头加一个标签，段中不再加。

### 3.2 推荐标签池（传记基调）

**常用（首选）**：

| 标签 | 适用场景 |
|---|---|
| `[平静地]` | 默认叙述基调，最大宗使用 |
| `[缓缓地] | 时间跨度较大的回顾、童年段落 |
| `[平稳地]` | 平铺直叙的事实交代 |
| `[平静叙述地]` | 转场、过渡段 |
| `[自然叙述地]` | 节奏正常的推进 |
| `[自然过渡地]` | 章节切换处 |
| `[略带停顿]` | 关键转折前，制造呼吸 |

> **强制约束**：常用池中**不得**出现任何语速控制类标签（如 `[放慢语速]`、`[加快语速]`、`[提速]`、`[放慢]`、`[加快]`）。语速控制类修饰词属于"表演式导演指令"，TTS 引擎对它们的实际响应不一致，且容易造成节奏生硬、机械感增强。传记播客的节奏感应由**文字本身的标点和断句**承担，不靠括号指令强行调速。

**点睛（少量使用，全文不超过 8 处）**：

| 标签 | 适用场景 |
|---|---|
| `[语调略沉]` | 涉及失败、争议、低谷 |
| `[略带意味地]` | 反讽、伏笔、潜台词 |
| `[平静引用地]` | 引出人物原话前 |
| `[缓缓收束地]` | 全文最后一段 |

### 3.3 禁用标签

以下标签**一律禁用**——它们会让传记瞬间变成综艺感，或属于 TTS 引擎响应不可控的语速控制类指令：

**综艺感标签（AI 日报播客常用，传记禁用）**：

- `[热情欢快]` / `[热情欢快地]`
- `[一针见血]` / `[一针见血地]`
- `[激动地]`
- `[兴奋地]`
- `[俏皮地]`
- `[欢快地]`

**语速控制类标签（强制禁用）**：

- `[放慢语速]`
- `[加快语速]`
- `[放慢]`
- `[加快]`
- `[提速]`
- `[减速]`
- `[语速放慢]`
- `[语速加快]`
- 以及任何包含"语速""放慢""加快""提速""减速"字样的方括号标签

> 语速变化应由文本断句和标点自然带出（逗号产生轻顿、句号产生停顿、独立成段产生呼吸），不靠方括号指令注入。一旦脚本中出现上述任一语速控制标签，视为不合格产物，必须改写。

传记不要"欢快"，不要"一针见血"，也不要"放慢语速"。要平静、要留白，节奏由文字本身承担。

### 3.4 标签密度

- 全文段落数的 **70% 以上** 使用 `[平静地]` / `[平稳地]` / `[平静叙述地]` 这三类中性标签。
- 情绪色彩标签（`[语调略沉]` `[略带意味地]` 等）总占比不超过 20%。
- `[缓缓地]` `[略带停顿]` 这类节奏标签不超过 10%（注：`[放慢语速]` 等语速控制类标签已全面禁用，不计入此比例）。
- 同一标签**避免连续出现超过 3 段**，避免单调。

## 四、TTS 合成

### 4.1 工具

复用 `ai-daily-podcast` skill 的单人 TTS 脚本：

```bash
python3 scripts/generate_tts_solo.py \
  --content-file biography-{slug}/50_podcast_script.md \
  --output-file biography-{slug}/60_podcast.mp3
```

环境变量（从 `~/.zshrc` 加载）：
- `VOLCENGINE_TTS_APPID`
- `VOLCENGINE_TTS_SPEAKER`（推荐 `zh_male_wennuanahu_uranus_bigtts`，温暖男声）
- `VOLCENGINE_TTS_ACCESS_TOKEN`

### 4.2 参数经验值

| 参数 | 推荐值 | 说明 |
|---|---|---|
| `--max-chars` | 2000（默认） | 每段 TTS 上限，过长会超时 |
| 预期分段数 | 2-4 段（对应 3000-4000 字传记） | |
| 预期总时长 | 11-15 分钟 | 96kbps MP3，约 6-10 MB |
| 合成耗时 | 3-5 分钟 | 建议用 `run_in_background: true` |

### 4.3 执行流程

1. **后台执行** TTS 命令（`run_in_background: true`），避免阻塞。
2. 系统会在任务完成后自动发 `<task-notification>`，**不要主动轮询**。
3. 完成后用 `ffprobe` 验证时长与文件大小：
   ```bash
   ffprobe -v error -show_entries format=duration,size,bit_rate \
     -of default=noprint_wrappers=1 biography-{slug}/60_podcast.mp3
   ```
4. 用 `present_files` 交付 `50_podcast_script.md` 和 `60_podcast.mp3`。

## 五、交付清单

阶段 6 完成后向用户提供：

| 文件 | 说明 |
|---|---|
| `50_podcast_script.md` | 播客脚本（含情感标签） |
| `60_podcast.mp3` | 最终音频 |

并在对话中给出：
- 音频时长（分秒）
- 文件大小（MB）
- 脚本字数
- 使用的主播音色 ID

阶段 6 是**可选**阶段，以下任一条件触发：

- 用户明确要求"转成播客"/"生成音频"/"做成单人播客"
- 用户引用 `40_final.md` 并要求转音频
- 用户在传记完成后主动追加音频需求

默认**不自动执行**阶段 6，需要用户显式触发。
