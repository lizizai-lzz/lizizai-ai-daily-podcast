# 内容互补矩阵

三条播客的内容分配规则。核心原则：**每条新闻只出现在一条播客中，零重叠。**

> **行业洞见独立运行**：它不从 AI 日报分配内容，也不要求另外两栏同时生成。完整运行 `references/industry-research.md` 后直接进入母文、大纲和脚本。

---

## 分配规则总表

### 三栏通用硬排除

每日精选、开源解读、行业洞见都只排除以下两类：

- **Agent 安全**：沙箱隔离、权限与身份、提示注入、工具投毒、供应链攻击、越权执行、红队攻防等以智能体安全为核心的内容。
- **漏洞**：漏洞发现、复现、利用、披露、补丁、CVE、代码扫描与攻击事件。

隐私、监管、合规、诈骗、内容安全、可靠性、模型对齐等相邻主题不自动排除，按具体内容判断。

### 每日精选

- **内容来源**：从所有日报模块中挑选 10 条最有话题性的 AI 热点新闻
- **排除**：纯开源项目、纯融资数据、纯论文
- **排序**：按话题性和讨论价值从高到低
- **固定数量**：10 条

### 开源解读

- **内容来源**：从开源速递模块中挑选 5 个项目
- **筛选标准**：独立开发者/一人公司/超级个体能否直接用来赚钱或提效
- **排序**：按独立开发者价值从高到低
- **固定数量**：5 个

### 行业洞见

- **核心内容**：只讲一个观点，讲深讲透。从知乎 AI 大众热点中选取普通用户、职场人或学生会关心的问题，再用外部材料核验；不读取 AI 日报
- **受众优先级**：普通 AI 用户、职场人、学生、家长、消费者优先于独立开发者
- **默认排除**：Agent 安全与漏洞两类核心主题；不扩大到其他安全相关议题
- **选题证据**：先看知乎热度和讨论，再用至少 3 条外部可信来源核验事实
- **论证结构**：三层论证（现象层→因果层→行动层），01fish 倒叙体
- **观点选择标准**：有冲击力、有解读空间、和全天内容有呼应
- **论证方式**：每层用 3 个论据支撑，论据来自全天各模块 + DailyAINewsWiki 知识库历史纵深
- **不覆盖其他趋势**：一个观点到底，不讲第二个
- **标题规则**：有人物原话用「人物:观点」，公共话题用「话题:判断」，视觉宽度不超过 20

## 模块分配参考

以下为各模块内容的倾向性分配，**非硬性规则**，以选题判断时的实际内容为准：

| 日报模块 | 倾向分配 | 说明 |
|----------|---------|------|
| 今日概览 | 每日精选 | 作为开场引入 |
| 头条聚焦 | 视内容而定 | 格局/趋势类→行业洞见；产品类→每日精选；Agent 安全与漏洞两类不入选 |
| 开源速递 | 开源解读 | 精选 5 个项目，其余不入选 |
| 模型与产品 | 每日精选 | 主要在每日精选中覆盖 |
| 头部厂商动态 | 视内容而定 | 格局类→行业洞见；产品类→每日精选 |
| 融资与投资 | 每日精选或独立行业洞见外部研究 | 不作为行业洞见日报输入 |
| 观点与言论 | 每日精选 | 行业洞见不从日报观点取材 |
| 研究与论文 | 不入选 | 三条播客均不覆盖 |

---

## 零重叠规则

1. 同一条新闻/项目只能在一条播客中出现
2. 如果某条内容同时适合多条播客，按以下优先级分配：
   - **开源项目** → 开源解读（无条件优先）
   - **融资数据** → 行业洞见（仅作论据）
   - **其余** → 按选题判断时的"最有话题性"和"最合适"原则灵活分配
3. 每日精选和行业洞见之间不设硬性模块边界，但同一条新闻不能重复

---

## 空模块处理

| 缺失模块 | 处理方式 |
|----------|---------|
| 无开源项目 | 开源解读跳过不生成 |
| 无融资数据 | 行业洞见独立研究，不受影响 |
| 无 Builder 观点 | 行业洞见独立研究，不受影响 |
| 无头条聚焦 | 每日精选从其他模块补充 |
| 无模型产品 | 每日精选从其他模块补充 |
| 无厂商动态 | 各播客跳过，不强行填充 |
| 无研究与论文 | 正常，不入选任何播客 |
