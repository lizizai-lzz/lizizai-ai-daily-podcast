# 模块：每日精选

> **加载范围**：只在你负责生成「每日精选」这一条时完整读取本文件。共用流水线（Phase 0 知识库与去重、Phase 1 选题、Phase 2.5 config.json、Phase 2.6 后处理、Phase 3 音频与封面、Phase 4 交付）见 `../SKILL.md`。
> 本模块的产物：`script_daily_brief_{date}.md`（双人联播）。

## 播客定位

- **名称**：李自在AI日报 | 每日精选
- **时长**：8-12 分钟（10 条新闻 × 约 1 分钟解读）
- **字数范围**：2400-3600 字（低于 2400 字内容不够充实，超过 3600 字音频过长）
- **格式**：双人联播（A = 李自在，男声；B = 肖然，女声），10 条新闻由两位主持交替播报，条目之间插入翻页音效，使用火山引擎 TTS 情感标签控制语调
- **受众**：独立开发者 / 一人公司 / AI 领域创业者
- **核心定位**：两位主持像新闻联播一样一人播一条，盘点今天 AI 圈最值得聊的 10 条热点新闻，每条都有观点点评

## 品牌口播（固定，每期必含）

开场品牌口播与收尾品牌口播是三条播客共用的，原文见 SKILL.md「品牌口播」。本模块只需要用下面这句交叉推荐：

> "今天的每日精选就到这里。想听今天的开源项目深度解读可以听**开源解读版**，行业格局和融资分析听**行业洞见版**。"

## 标题生成规则（每日精选专用）

每日精选播客的标题使用**「头条新闻法」**：从当天 10 条新闻中选出**最劲爆的 1 条**作为标题主角，围绕它生成标题。**禁止双话题并列**（如"OpenAI 降价与 AI 资本化潮""OpenAI 定档2027，Qwen3.8 下周开源"），15 字预算下两条各剩半截，语义必然残缺，辨识度反而不如单条讲透。

### 头条新闻的选取优先级

1. **冲击力优先**：全球首例、破纪录、反直觉、重大转折（如"全球首例 AI 经理开除人类员工""Anthropic 冲击 SpaceX 级 IPO"）
2. **新鲜度**：当天首次发布的新闻 > 持续报道的进展
3. **与独立开发者的相关性**：直接影响做产品/赚钱判断的新闻（涨价、降价、开源、政策）

### 标题要求

**字数**：15-20 字，**信息完整优先于字数**。宁可多 2-3 个字，也要把"谁 + 做了什么 + 关键限定"说全，禁止为了卡字数牺牲语义。

**必须包含**：
- 明确的主体（公司/产品/人物）
- 具体的动作或事件（做了什么/发生了什么）
- 关键限定（数字、时间、对象、程度），这是区分"今天"和"任何一天"的辨识度来源

**禁止**：
- 双话题并列（除非是同一事件不可分割的两个侧面）
- 模糊归纳词：如"新政策""资本化潮""大动作""巨变"，这些词放哪天都成立，没有信息量
- 缩略语/隐语：如"定档2027"必须写成"最迟 2027 上市"

### 反例与正例对照（来自真实近期标题）

| 反例（语义残缺） | 问题 | 正例 |
|------|------|------|
| `OpenAI 定档2027，Qwen3.8 下周开源` | 双话题各剩半截，"定档2027"不明所指 | `OpenAI 最迟 2027 上市，Qwen3.8 下周开源` |
| `OpenAI 降价与 AI 资本化潮` | "资本化潮"模糊，最劲爆的 IPO 信息丢失 | `Anthropic 冲击 SpaceX 级 IPO` |
| `AI 经理开除人类员工` | 丢了"全球首例"这个最劲爆的限定 | `全球首例：AI 经理开除人类员工` |

### 标题自检清单

- [ ] 标题只讲一条新闻？（双话题并列 → 失败）
- [ ] 主体、动作、关键限定三者齐全？（缺一个 → 语义不完整，重写）
- [ ] 没有模糊归纳词？（"新政策""潮""大动作" → 失败）
- [ ] 单独看标题，能说出"今天发生了什么"吗？

## 内容范围

从选题判断结果中获取分配给每日精选的 **10 条热点新闻**。

### 禁止出现的内容

以下内容已被其他播客覆盖，严禁在本脚本中出现：
- ❌ 任何开源项目（归开源解读）
- ❌ 任何融资数据（归行业洞见）
- ❌ 任何 Builder 观点（归行业洞见）
- ❌ 任何论文或学术研究内容

### 三栏通用内容排除

每日精选只排除以下两类新闻：

- **Agent 安全**：以智能体沙箱、权限、身份、提示注入、工具投毒、供应链攻击、越权执行、红队攻防为核心。
- **漏洞**：以漏洞发现、利用、披露、补丁、CVE、代码扫描或攻击事件为核心。

隐私、监管、合规、诈骗、内容安全、可靠性、模型对齐等主题不自动排除，仍可根据新闻价值入选。

## 脚本格式：火山引擎 TTS 情感标签

每日精选使用双人联播 TTS 生成，脚本必须使用 `A: [情感描述] 文本` / `B: [情感描述] 文本` 格式控制语调和节奏。

### 情感标签格式

```
A: [情感描述] 紧跟要朗读的文本
B: [情感描述] 紧跟要朗读的文本
```

**示例**：
```
A: [热情欢快地]欢迎收听李自在AI日报，我是李自在。
B: [平静地]我是肖然。今天 AI 圈炸了一条大新闻，Claude 4 真的来了。
A: [郑重地]我们从里面挑了 10 条最值得聊的，一条一条看。
```

## 口语化生成规范（每日精选专属，强制）

> **适用范围**：这一节只管每日精选。三栏目分轨（双人盘点 / 单人开源 / 单人行业），但**语气词与 TTS 禁区同一套标准**；人称密度线不同（每日精选 ≥ 20，开源解读与行业洞见 ≥ 25）。不要把每日精选的双人结构套到另外两栏，也不要照搬它们的特有写法。（2026-09-28 分轨；2026-10-13 起语气词改为软建议，见下）

### 为什么要有这一节

**这份稿子的问题从来不是句子太长，而是"说话的人不在场"。** 2026-09-28 的稿子实测：句尾语气词 0、人称词 4.1、问句 0（每千汉字）；同期 9 档真实中文播客的均值是 13.5 / 34.0 / 5.5，而平均句长我们 12.3 对人家 12.7，几乎一样。**把句子拆短不解决问题**，缺的是人、语气和提问。

口语感应靠**人称、真问句、起句衔接**（"我/你/我们""那……""所以说""我关心的是"），**不靠堆语气词**。硬凑「啊/呢/吧/嘛/呀」到专有名词和事实句尾，火山 TTS 会把尾音念得很重，听感难受。

**写作前必读** `references/voice-samples.md`（12 段真实中文播客开头的完整转写、逐项密度、六条写法）。写完必须跑：

```bash
python3 scripts/check_oral_voice.py {script_path}
```

### 主指标（每千汉字）

| 指标 | 要求 | 过检 | 说明 |
| --- | --- | --- | --- |
| 人称词（我/我们/你/大家/咱们） | ≥ 20 | **硬 FAIL** | 判断句要有人；"对做产品的人来说"这类无主语句不能占满全篇 |
| 问句 | ≥ 2.5 | **硬 FAIL** | 向听众提问或跟搭档确认，每 2 分钟至少 3 个；必须是真问句 |
| 书面连接词（因此/综上/值得注意/意味着） | ≤ 2 | **硬 FAIL** | 换成"那……""所以说""我关心的是" |
| 平均句长 | 8-18 字 | **硬 FAIL** | 不要靠拆短句解决，句子长度本来就没问题 |
| 句尾语气词（啊/呢/吧/嘛/呀） | 约 2–5，宁少勿滥 | **仅 WARN** | 不足不再 FAIL；超过约 8 也 WARN。口语主指标是人称与问句，不是语气词 |

### TTS 语气词禁区（硬约束）

以下位置**禁止**加 啊 / 呢 / 吧 / 嘛 / 呀：

1. **专有名词后**（产品名、公司名、人名、型号）：❌「Muse Wonder Full 呢」「Decart 啊」
2. **数字 / 评分 / 基准分后**：❌「都高啊」「四万五千颗星啊」「五十六分呢」
3. **纯事实陈述句尾**：❌「第一批成果呢」「可能近期就达成呢」「都谈崩了呀」

**允许**出现在：

- 真人会犹豫、缓和、确认的地方（"对吧？""我还是要说一句"）
- **真正问听众的问句**里（"那落到我们身上是什么？""跟我有什么关系？"）

同一段结尾不要连续堆多个语气词。

### TTS 干净稿规则（每日精选默认）

- 人读版可以稍口语；**进火山 TTS 前必须过一遍清语气词**——删掉专名 / 数字 / 纯事实句后的尾音，同一段结尾不要连续多个语气词。
- **每日精选默认直接产出 TTS 干净稿**（流水线走火山 TTS，不另出"人读加语气词版"）。
- 清语气词时**保留**人称词与真问句，不要为了"干净"把"我/你/我们"和问号一起删掉。

### 外部范例（语感参考，禁止照抄选题和结构）

以下 5 段全部来自真实中文播客的开头（完整 12 段见 `references/voice-samples.md`）。转写由语音识别生成，人名和专有名词可能有同音错字，**只做语感参考，不要当事实引用**。**范例来自真人录音转写，TTS 稿语气词应明显更少**——只学他们怎么起句、怎么把判断落到"我"和"你"身上，不要学他们往专名和数字后塞语气词。我们是 10 条新闻盘点，不是访谈，**结构一律不要照搬**。

**一、硅谷101（单人科技口播）**

> 哈喽大家好，欢迎回到硅谷101，我是艺文。
> 很多投资人呢在和我们聊天的时候啊，都提到了他们最近很关注的一个赛道，那就是数据。
> 今年 4 月宣布 A 轮融资的时候，估值还是 3 亿美元。到了九月呢，新一轮融资就已经把它的估值推到了 32 亿美元，不到半年啊涨到了十倍之多。

要点：由头是"谁跟我说的"；句子短、逗号密。注意：范例里数字前后带语气词是真人转写特征，**TTS 稿不要照抄这种密度**。

**二、十字路口（双人访谈）**

> 那本周的嘉宾是于红。
> 那今天的于红带着他的作品啊，一套叫涂东东的社会情感学习来到了十字路口。
> 你好于红，欢迎来到十字路口。

要点：开场就是招呼加报名；直接对嘉宾说话；"哎""那"用来起句。

**三、张小珺（单人访谈）**

> Hello，大家好，我是小俊。今天我们的嘉宾是企业战略专家曾教授。
> 曾教授是阿里巴巴集团前总参谋长……
> 呃，听完让我觉得有了更全局的视角。

要点：主播说出"我"的听后感，不装客观。

**四、科技早知道（双人）**

> 用声音碰撞世界。
> Hello，大家好，欢迎来到我们今天的科技早知道，我是雅娴啊。
> 那最近呢 Google DeepMind 出现了一轮引发激烈讨论的人事和组织变化啊。
> 那与此同时呢，在谷歌效力了 27 年的首席科学家 Jeff Dean 与其他三位核心成员一起离开。

要点：先招呼再交代事；"那……"做衔接；专有名称照读。TTS 稿里"那最近 Google DeepMind……"即可，不必在专名后加「呢/啊」。

**五、硬地骇客 / 面基（对话密度参照）**

> 大家好，欢迎收听硬地骇客，我是赛 to，我是一笑。
> 因为很多人想象中的硬地骇客可能是很自由的啊。
> 你的工作其实就是达成老板的目标嘛。
> 我们是这样的，嗯，有个灯下黑的情况嘛。

要点：判断句里一直有"你"；允许少量填充。TTS 稿以人称为主，语气词宁少勿滥。

### 一条新闻的前后对照（每日精选自己的例子）

❌ 死板播报（2026-09-28 原稿）

```
A: [语气平稳] OpenAI 的回应是，直到八月公司才知情，被访问的澳大利亚政府站点至少四处，没有造成个人隐私泄露。
A: [语气专注] 这是智能体越界第一次被提到"境外政府部门传唤首席执行官到场"的级别。责任主体从模型，明确落到了厂商高管身上。
A: [语气沉稳] 对做产品的人来说，监管要问的第一句大概率是"你怎么知道它没越界"。模型强不强，排在后面。
```

❌ 硬塞语气词版（凑密度，TTS 难听）

```
A: [语气平稳] OpenAI 呢回应是，直到八月公司才知情啊，被访问的站点至少四处呢……
```

✅ TTS 干净人话版（同一条；人称 + 真问句，语气词不进禁区）

```
A: [语气平稳] 那 OpenAI 怎么说？他们说公司直到八月才知道，被访问的政府站点至少有四处，没造成个人隐私泄露。这是他们自己给的版本。
A: [语气专注] 我关心的是另一个问题。监管现在问你的第一句，是你怎么知道它没越界，模型强不强，排在后面。那怎么证明呢？访问日志、授权边界、目标站点的合规说明，这三样你以后都得拿得出来。
```

信息一条没少，差别全在"谁在说、跟谁说"；问句里的「呢」可以留，专名和事实句尾不要加。

### 判断句落到人身上

| 念稿腔 | 人话 |
| --- | --- |
| 这意味着依赖单一模型接口的团队会被动承接合规要求 | 你要是只靠一家的模型接口，以后很可能被上游推着走 |
| 值得注意的是它的定位，它不造整机 | 它自己不造整机，卖的是芯片和平台 |
| 对独立开发者来说，数据来源要留下记录 | 那落到我们自己身上呢？来源、许可证、获取时间，都记进数据卡 |
| 这组数字有两层含义 | 什么概念呢？ |
| 这项技术将显著降低使用门槛 | 你说自建成本是不是又降了一档？ |

### 三条禁令

1. 不用"这意味着""值得注意的是""换句话说"起句，换成"那……""所以说""我关心的是"
2. 不允许连续三段完全没有"我/我们/你/大家"，第三人称判断不能连排
3. **不靠堆语气词硬凑密度**；专名后、数字/评分后、纯事实句尾禁止加 啊/呢/吧/嘛/呀；问句要问听众真的会问的问题。过检时语气词不足只 WARN，人称或问句不足才 FAIL

## 双人播报规则（硬约束）

**一句话规则：一条新闻 = 一位主持从头说到尾。A 说完整整一条，才轮到 B；B 说完整整一条，才轮到 A。两位主持不穿插、不接话、不在别人的条目里出声。**

1. **一条新闻只由一位主持读完（最重要的硬约束）**：被 `===` 分隔出的每个新闻区块内，**所有行必须是同一个前缀**，要么全 `A:`，要么全 `B:`。事实播报、观点点评、过渡衔接都由这一位主持说完，另一位主持在这个区块里**一行都不出**，不补充、不追问、不捧哏、不总结
2. **换人只发生在 `===` 之间**：条目内部禁止换人。点评不是"另一个人接话"，而是本条主持自己的判断，这条是 A 的，点评就用 A 的口吻写；这条是 B 的，点评就用 B 的口吻写

   ❌ 错误（两人穿插，一条新闻被拆成对话）：
   ```
   A: [语气认真] 第一条，OpenAI 发布了新模型……
   B: [语气专注] 这条的意义在于能力边界又外扩了一圈。
   A: [语气平稳] 对独立开发者来说……
   ```

   ✅ 正确（一位主持读完一整条，另一位这一条完全不出现）：
   ```
   A: [语气认真] 第一条，OpenAI 发布了新模型……
   A: [语气专注] 这条的意义在于能力边界又外扩了一圈。
   A: [语气平稳] 对独立开发者来说……
   ```

3. **交替顺序固定**：第 1 条 A（李自在）、第 2 条 B（肖然）、第 3 条 A……直到第 10 条。切换点就是 `===`，不是段与段之间
4. **条目之间用单独一行的 `===` 分隔**（三个等号），不要用 `---`
5. **每条内部**仍是"事实播报 → 观点点评 → 过渡"，2-3 行即可，全部由本条主持念，过渡句也由他说完，下一条直接换人，不写"下面请听"这类交接词
6. **B 不是捧哏**：她播的条目要有和 A 同等的信息量和判断，只是那些判断说在她自己的条目里，不跑到 A 的条目里接话
7. **开场与收尾是唯一例外**：开场区块（第一个 `===` 之前）允许 A 报品牌、B 自报家门、A 引出第一条；收尾区块（最后一个 `===` 之后）允许 A 总结、B 交叉推荐、A 收尾品牌口播。除此之外任何区块都不许混用前缀
8. **机械自检（写完必做）**：把脚本按 `===` 切块，逐块检查块内是不是只有一种前缀。TTS 脚本 `generate_news_broadcast.py` 会做同一项检查，块内混用 A/B 会直接报错拒绝录制

### 情感标签规则

1. **每段至少 2-3 个情感变化**，让播客有层次感
2. **情感描述越具体效果越好**：
   - 好：`[用低沉神秘的声音]` `[边笑边说]` `[压低声音悄悄说]`
   - 差：`[开心]` `[难过]`
3. **推荐的情感标签**：
   - 开场/总结：`[热情欢快地]` `[平静地]` `[轻松自然地]`
   - 抛观点：`[严肃认真地]` `[语气坚定地]` `[直截了当地说]`
   - 震撼数据：`[略带惊讶]` `[难以置信地]` `[感叹地]`
   - 犀利点评：`[一针见血地]` `[毫不客气地说]` `[意味深长地]`
   - 过渡转折：`[稍作停顿]` `[语调上扬]`
4. **语速标签禁令（强制）**：`[放慢语速]`、`[加快语速]`、`[放慢]`、`[加快]`、`[提速]`、`[减速]` 及任何含"语速/放慢/加快/提速/减速"字样的方括号标签一律禁用。节奏感由文字标点和断句承担，不靠括号指令
5. **不要使用** Fish Audio 的 `[pause]` `[laugh]` `[gasp]` 等英文标签

## 开头方式（每篇从以下 5 种手法中选 1 种，不要每次选同一种）

每日精选的开场不应该是固定的"今天 AI 圈发生了很多事"模板，这种半填空模板每期听起来都一样，几期之后就被听众识别为机械开场。以下 5 种写作手法是**生成开场口播的指引**，不是写好的成品话术：选定一种手法后，结合当天 10 条新闻的具体内容生成对应的开场。

| 手法 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **头条先行** | 用今天最炸的一条新闻开场，一句话点燃，再展开"还有 9 条值得听" | 当天有压倒性头条（大模型发布、重磅融资、突发政策）时优先 | "OpenAI 今天凌晨放了个大招，GPT-5 正式发布了。但今天值得聊的不止这一条。" |
| **冲突对立** | 从今天新闻里提炼出一组对立信号（开源 vs 闭源、大厂 vs 创业公司、乐观 vs 悲观），用对立制造张力 | 当天多条新闻呈现明显分化或对立格局 | "今天这十条新闻放一起看，特别有意思，一半在说大模型越来越强，另一半在说应用层正在洗牌。" |
| **趋势钩子** | 不讲具体新闻，先抛一个跨多条新闻的共性趋势判断，勾起"为什么这么说"的好奇 | 当天多条新闻指向同一个底层趋势（如"所有人都在卷 Agent""成本在快速下降"） | "看完今天的十条，我有个判断。这一周 AI 圈的关键词是'更便宜'，'更强'反而排在后面。" |
| **场景代入** | 描述一个独立开发者会遇到的具象场景（写代码、调 API、看 GitHub Trending），从场景自然拉到新闻 | 当天新闻偏工具层、开发者日常相关时适合 | "如果你今天打开 GitHub Trending，会发现首页有三个项目跟昨天完全不一样。AI 这一周变化太快了。" |
| **反常信号** | 指出今天新闻里某个反直觉或反共识的细节，制造"咦？"的停顿 | 当天有"看似小事但影响大""数据反常""大厂反常沉默"等信号时适合 | "今天最值得聊的新闻，Star 数其实并不高。但它的提交记录，比那些刷榜项目诚实多了。" |

### 使用规则

1. **每期只选 1 种手法**，开场口播控制在 2-4 句话、不超过 80 字
2. **7 天轮换约束**：近 7 天内用过的手法不得重复，查 `podcast_history.md` 确认上一期每日精选用的是哪种手法，避开它
3. **手法选择依据**：由当天 10 条新闻的内容特征决定，不要凭个人偏好固定某一种
4. **开场口播落在谁身上**：品牌口播之后，由 B（肖然）承接本条手法开场的正文，再由 A（李自在）用一句话引入第一条新闻（如"十条里面，最重的一条来自{主体}"），然后进入第一条。这三行都在开场区块内（第一个 `===` 之前），两位主持在这里各说一句是允许的；从第一条新闻开始，一条新闻只由一位主持读完

## 每条新闻的解读结构（约 1 分钟）

| 部分 | 内容 | 时长 |
|------|------|------|
| 事实播报 | 新闻核心事实，简洁有力 | 15-20 秒 |
| 观点点评 | 深入分析 + 独立开发者视角 | 20-30 秒 |
| 过渡衔接 | 自然引出下一条 | 5-10 秒 |

### 点评要求

- 每条新闻必须有实质观点，不能只是复述
- 要有"对独立开发者意味着什么"的视角
- 适当用反问、延伸来制造思考空间
- 可以质疑、可以赞叹，观点要鲜明

## 格式结构

```
[标题行] 李自在AI日报 | 每日精选 — {date}

[开场区块] A 报品牌 → B 自报家门 + 从「开头方式」菜单选 1 种 → A 引出今天的 10 条精选
  （只有这个区块允许 A/B 混用）
  A: [热情欢快地]欢迎收听李自在AI日报，我是李自在。
  B: [平静地]我是肖然。{从「开头方式」菜单选 1 种写作手法，生成对应的开场口播}
  A: [郑重地]十条里最重的一条来自{主体}。

===

[新闻 1] 由 A 播报：这个区块内每一行的前缀都必须是 A:
  A: [情感描述] 第一条，{事实播报}
  A: [情感描述] {观点点评}
  A: [情感描述] {过渡}

===

[新闻 2] 由 B 播报：这个区块内每一行的前缀都必须是 B:
  B: [情感描述] 第二条，{事实播报}
  B: [情感描述] {观点点评}
  B: [情感描述] {过渡}

  …… 奇数是 A，偶数是 B，交替到第 10 条；换人只发生在 === 处，条目内部不换人

[收尾区块] 约 30 秒（与开场一样允许 A/B 混用）
  A: [温暖地]总结今天的 10 条新闻中最大的趋势或共性
  交叉推荐（开源解读版 + 行业洞见版）
  收尾品牌口播
```

## 完整脚本示例（片段）

```
# 李自在AI日报 | 每日精选 — 2026-05-20

A: [热情欢快地]欢迎收听李自在AI日报，我是李自在。

B: [平静地]我是肖然。今天 AI 圈炸了，最大的看点是 Claude 4 正式发布了。

A: [郑重地]十条里最重的一条来自谷歌。

===

A: [平静地]第一条，谷歌发布了 Gemini 2.5 的正式版。这个版本在编程能力上有了显著提升，Benchmark 跑分直接超过了 GPT-4o。

A: [一针见血地]这意味着什么？开源和闭源的差距在加速缩小。对独立开发者来说，多了一个强有力的选择，而且 Gemini 的 API 定价一直比 OpenAI 便宜。

===

B: [略带惊讶]第二条，Anthropic 这次直接跳过了 3.5 的迭代，出了 Claude 4。性能提升不是一点点，在长上下文推理上直接碾压了上一代。

B: [语气坚定地]我的判断是，这轮模型升级的赢家不是参数最大的那个，而是应用场景最贴合的那个。对做产品的独立开发者来说，赶紧试试 API，看看哪个模型在你的场景下表现最好。

===

A: [轻松地]第三条，……
```

注意示例里每个 `===` 区块内部都只有一种前缀：第一条从头到尾是 `A:`，第二条从头到尾是 `B:`。写成 `A:` 一段、`B:` 接一段再回 `A:` 是不合格的，那等于两人合播一条新闻。

## 写作规则

- 口语化表达，像一个人在电台里跟你聊新闻
- 可以用第一人称表达观点和判断（"我觉得""我的判断是"）
- 句子简短，单句不超过 25 字为佳
- 不用 emoji、表格、代码块、URL
- 所有事实必须来自源内容，不编造
- 每条新闻要有"对独立开发者意味着什么"的视角
- 话题之间自然过渡，不用"接下来我们聊..."这种机械过渡
- **必须使用 `[情感描述]` 标签**，每段至少 2-3 个情感变化
- **语速标签禁令**：`[放慢语速]`、`[加快语速]` 等含"语速/放慢/加快"字样的标签禁用，节奏由标点断句承担
- **数字与单位转换**：日期禁止斜杠（`7/20` ➔ `7月20日`），单位必须汉化（`10px` ➔ `10像素`、`$100` ➔ `100美元`），年份逐位念（`2024年` ➔ `二零二四年`），"2"量词前读"两"（`2亿` ➔ `两亿`）。详见 SKILL.md Phase 2.6C
- **条目内不换人（硬约束）**：每个 `===` 区块内只能出现一位主持的前缀，事实、点评、过渡全由他念完，另一位在这一条里一行都不出现
- **口播声纹（硬约束）**：写成人在说话，不是念稿。主指标是人称 ≥ 20、问句 ≥ 2.5（每千字），语气词为软建议且遵守 TTS 禁区；详见上方「口语化生成规范」。写作前先读 `references/voice-samples.md`（范例语气词密度高于 TTS 稿，只学语感）
- **后处理（强制）**：脚本生成后必须经 de-AI-writing 去 AI 味润色 + 情感标签修正 + 数字单位转换，由 SKILL.md Phase 2.6 统一执行

## 生成前的知识库查询（本模块，强制，不可跳过）

使用 Read/Glob/Grep 工具直接读取 `~/Documents/DailyAINewsWiki/`。查询结果允许为空，但查询动作不可省略。审计记录的写法见 SKILL.md Phase 2 的「验证检查点」，写入 `knowledge_audit_{date}.md`。

**每日精选（10 条热点新闻）**：
- ✅ 使用 `Grep` 在 `wiki/entities/` 中搜索每条新闻涉及的核心实体（公司/产品），了解其历史脉络（无匹配则标注"首次出现"）
- ✅ 使用 `Grep` 在 `wiki/entities/` 中按 `type: person` 搜索新闻中引用的人物，确认其立场一致性（无匹配则标注"首次提及"）
- ✅ 使用 `Read` 读取 `wiki/sources/` 中最近 3 天的 `daily-*.md` 日报页，检查新闻是否曾被报道，如曾报道，脚本中用"上次我们聊到 XX 的时候还是三天前，今天它又..."的方式自然衔接
- **目标**：让每条新闻不孤立，听众感受到这是一个持续追踪的故事

## ⚠️ 输出格式硬约束（强制，违反即判不合格）

**本提示词上方所有「播客定位」字段（名称/时长/字数范围/格式/受众/核心定位）都是给你看的设计参数，不是要写进脚本的内容。** 它们只决定你怎么写，绝不能出现在输出里。

### 脚本必须长这样（精确到第一行）

```
# 李自在AI日报 | 每日精选 — {YYYY-MM-DD}

A: [情感描述] 欢迎收听**李自在AI日报**，我是李自在。

B: [情感描述] 我是肖然。{开场引出 10 条新闻的口播} ……

===

A: [情感描述] 第一条，……

A: [情感描述] {这条新闻的点评}……
```

**第 1 行**：必须是 `# 李自在AI日报 | 每日精选 — {date}` 格式的 H1 标题，**必须保留「李自在AI日报 | 」品牌前缀**（不能简写成「每日精选 — {date}」）。
**第 2 行**：必须是空行。
**第 3 行起**：直接进入 `A: [情感描述]` 品牌口播，中间不能有任何其他内容。
**条目分隔**：每条新闻之间用单独一行的 `===` 分隔，这是唯一的合法分隔符。
**条目内单一主持**：第一个 `===` 之后、最后一个 `===` 之前的所有区块，块内每一行前缀必须相同；混用即判不合格。

### 严禁出现在脚本中的元素（出现任意一条即不合格）

| 禁止元素 | 原因 |
|---------|------|
| ❌ Markdown blockquote 引用块（`> xxx`） | 会被 TTS 朗读出来，且不是口播内容 |
| ❌ Markdown 水平分隔线（`---`） | 会被当成分隔符误切分；条目分隔一律用 `===` |
| ❌ 「时长目标：8-12 分钟」「字数范围：2400-3600 字」这类规格说明 | 这是设计参数不是脚本内容 |
| ❌ 「双人联播·10 条 AI 热点新闻」这类定位描述 | 同上 |
| ❌ YAML front matter（`---\n...`） | 同上 |
| ❌ 任何「## 章节」「### 标签说明」之类的元信息 | 脚本只允许 H1 标题，不允许其他 heading |

**自检一**：把脚本前 6 行单独抽出来看，如果第 3 行不是 `A: [情感描述] 欢迎收听...`，就不合格。

**自检二（条目内单一主持）**：把脚本按 `===` 切块，从第二块起逐块检查前缀是否唯一。最稳的做法是直接跑官方检查脚本：

```bash
python3 scripts/check_broadcast_speakers.py {script_path}
```

输出出现 `FAIL` 就说明有新闻被两位主持合播了，必须改回一个人读完再录。

**自检三（口播声纹）**：跑密度检查。人称词、问句、书面连接词、平均句长是硬线；语气词不足或偏多只 WARN。

```bash
python3 scripts/check_oral_voice.py {script_path}
```

出现人称/问句 `FAIL` 就回去补"人在场"：判断句改用"我/我们/你"起头，加真问句（"那落到我们身上是什么？"），不要往专名和数字后塞语气词。参考上方「TTS 语气词禁区」和「一条新闻的前后对照」。
