# 模块：行业洞见

> **加载范围**：只在你负责生成「行业洞见」这一条时完整读取本文件，并在选题前完整读取 `../references/industry-research.md`。共用流水线（Phase 0 去重、Phase 1 选题、Phase 2.5 config.json、Phase 2.6 后处理、Phase 3 音频与封面、Phase 4 交付）见 `../SKILL.md`。
> 本模块的产物：`industry_topic_selection_{date}.md`、`research_supplement_industry_{date}.md`、`source_brief_{date}.md`、`outline_{date}.md`、`script_industry_trends_{date}.md`，以及可独立生成的单条 `config.json`、封面和 MP3。
> **独立输入**：行业洞见不从 AI 日报选题，不读取 `ai_news_{date}.md`，也不要求日报套餐同时运行。

## 播客定位

- **名称**：李自在AI日报 | 行业洞见
- **时长**：7-10 分钟
- **字数范围**：2000-3000 字（低于 2000 字没讲透，超过 3000 字听众走神）
- **格式**：单人深度观点，使用火山引擎 TTS 情感标签控制语调
- **受众**：普通 AI 用户、职场人、学生、家长和消费者优先；独立开发者是其中一部分，不再是默认受众
- **铁律**：**只讲一个观点。把这个观点讲穿、讲透，讲到听众没法反驳。** 不讲第二个。
- **选题入口**：从知乎 AI 大众热点里找普通人有感的问题，再用 DeepSeek Search / Fetch 到公开原文核验；不使用 AI 日报
- **默认排除**：只排除 Agent 安全与漏洞两类核心主题。隐私、监管、合规、诈骗、内容安全、可靠性、模型对齐等相邻话题不自动排除。

## 写作风格：01fish 观点输出体

本脚本的写作参考 01fish 观点输出类写作风格。核心特征：

- **口语化但有刀刃**：像一个人在电台里跟你认真分析，用"我"的亲历感和"你"的对话感
- **段落极短**：1-3 句为一段，大量单句成段（钉子段），敲钉式收束
- **先说结果，再说过程，最后给观点**（倒叙结构）
- **金句句式多样化**（见下方「金句与钉子段」规则），禁止每层都用同一个句式
- **数字必须具体**：不写"很多融资"，写"250 亿美元"
- **类比只来自生活/制造业**：禁止用技术概念解释技术概念
- **禁用词**：笔者、本文、众所周知、不可否认、在当今时代、随着 AI 的发展

## 标题生成规则（行业洞见专用）

行业洞见播客按来源选择两种标题格式之一：

- **人物来源**：使用「**人物:观点**」，适合找到一个明确发言者并用其原话开场。
- **公共话题来源**：使用「**话题:判断**」，适合知乎热点、社会讨论和大众困惑。话题部分写具体对象，判断部分写清楚结论，例如「年轻人的第一份工作:AI 正在收窄入口」。

### 公共话题标题规则

1. **话题必须是具体对象**：年轻人、家长、消费者、办公室、AI 眼镜、订阅费、求职入口，不能只写“AI”“未来”“时代”。
2. **判断必须可争论**：不能写“AI 很重要”“AI 改变生活”这种废话。
3. **视觉宽度 ≤ 20**：中文 1 字 = 1 宽；英文和数字每 2 个字符约 1 宽。
4. **标题不替正文提前列结构**：不要写“三个原因”“四层真相”“普通人必须知道的五件事”。
5. **标题避开两类主题**：以 Agent 安全或漏洞为核心议题时不选；不要因为标题里出现隐私、监管、合规、诈骗等词就自动排除。

### 人物来源标题规则

有人物来源时，继续使用「**人物:观点**」格式，从已核验的公开发言、访谈、社交媒体原帖或其他一手材料中选取最核心的人物和其一句话观点。

### 格式要求

```
<人物名>:<一句话观点>
```

### 人物名处理规则（中文优先，按知名度决定是否加 title）

与「李自在AI人物志」的命名逻辑保持一致：**中文优先，按知名度决定是否加 title，无查表流程，不调用 qiaomu-ds-search 查询中文名**。

1. **中文优先**：中文社区普遍使用的中文名直接采用（如 黄仁勋、马斯克、吴恩达、李飞飞）；中文社区习惯用英文原名称呼的知名人物，保留英文原名（如 Sam Altman、Dario Amodei）
2. **按知名度决定是否加 title**：
   - **非常知名的人物直接写人名，不加 title**，包括中文社区通用的中文名、中文社区通用的英文名（Sam Altman、Dario Amodei），以及业界用 ID/笔名称呼的人（如 Swyx）
   - **需要补充身份才能辨识的人物加 title**，格式「`{title} {英文原名}`」，title 选取规则：
     - 优先用人物当前的核心身份（公司 + 职位），如「a16z 普通合伙人 David George」「Vercel CEO Guillermo Rauch」「FirstMark 合伙人 Matt Turck」
     - 如果人物是知名创作者/独立研究者，用其领域 + 身份，如「AI 研究者 Ethan Mollick」
3. **无查表流程**：不读取 `references/people-zh-cn.md`，不依赖 qiaomu-ds-search 查询中文名，直接按上述规则判断

### 人物名判断流程

```
1. 判断该人物在中文社区是否有通用称呼
   ├─ 有中文通用名（黄仁勋、马斯克、吴恩达）→ 直接用中文名
   ├─ 中文社区习惯用英文原名（Sam Altman、Dario Amodei）→ 保留英文原名
   └─ 无通用称呼 ↓
2. 按知名度判断是否加 title
   ├─ 非常知名 / 业界用 ID 称呼（Swyx）→ 直接写人名，不加 title
   └─ 需要身份辨识 → 用「{title} {英文原名}」格式
3. title 选取：从已核验的公开人物介绍中获取（公司 + 职位；创作者/研究者用领域 + 身份）
```

### 其他规则

1. **观点原义不变**：从已核验的人物原始发言中摘取最核心的一句话判断，**严禁改写、转述、美化或添油加醋**，只允许删减不影响原义的修饰词
2. **字数**：原标题**视觉宽度不超过 20**（中文 1 字 = 1 宽；英文/数字每 2 个字符 ≈ 1 宽，如 `Aaron Levie` 约 6 宽、`Thibault Sottiaux` 约 8 宽），其中观点部分尽量控制在 **10 字宽以内**。超预算时按以下优先级压缩（**不得改变观点原义**）：
   - ① 先压缩观点部分：删副词/程度词/修饰语（如"即将变得极其快速"→"将极快"、"六分之一 AI 注册是滥用"→"六分之一注册是滥用"）
   - ② 再压缩人物 title：省略 title 或缩短身份（如"OpenAI 工程负责人 Thibault Sottiaux"→"Thibault Sottiaux"、"a16z 普通合伙人 David George"→"David George"）
   - ③ 最后仍超时，压缩观点中的非核心限定词（如时间、范围），核心判断一个词都不能动
3. **观点选取优先级**：
   - 优先选有争议性、有分析空间的判断（不是"AI 很重要"这类废话）
   - 优先选该人物最新、可核验的公开观点
   - 优先选涉及具体行动指引的观点（对普通听众有实际价值的）

## 口语化生成规范（行业洞见专属，强制）

> **适用范围**：这一节只管行业洞见。每日精选在 `modules/daily-brief.md`、开源解读在 `modules/opensource.md`。三条**人称密度线**不同（本栏 ≥ 25），但**语气词软建议与 TTS 禁区三栏同一套标准**，互不把特有写法套用。

### 为什么要有这一节

2026-09-28 的稿子实测：句尾语气词 0.0、**人称词 5.3**、问句 0.6（每千汉字），平均句长 12.3。同期 7 段"单人主讲 / 观点分析"类中文播客的均值是 **语气词 8.1、人称 34.6、问句 4.1、句长 13.6**。

人称 5.3 是三条播客里最低的，整篇稿子看不到说话的人，观点像是从天上掉下来的。同一份稿子还有 8 处中文冒号、1 处翻案腔（"通缩不是预测，是已经发生的会计事实"）、3 处洞察路标（这意味着 / 换句话说 / 真正的）。

口语感应靠**人称、真问句、起句衔接**（"我/你/我们""那……""所以说""我关心的是"），**不靠堆语气词**。硬凑「啊/呢/吧/嘛/呀」到专有名词和事实句尾，火山 TTS 会把尾音念得很重，听感难受。

**写作前必读** `references/voice-samples.md`，写完必须跑：

```bash
python3 scripts/check_oral_voice.py --type industry {script_path}
```

### 主指标（每千汉字）

| 指标 | 要求 | 过检 | 说明 |
| --- | --- | --- | --- |
| 人称词（我/我们/你/大家/咱们） | ≥ 25 | **硬 FAIL** | **这是行业洞见最缺的一项**。判断句必须有"我"，推演必须有"你" |
| 问句 | ≥ 2.5 | **硬 FAIL** | 每层论证至少一个问句，替听众把问题问出来；必须是真问句 |
| 书面连接词（因此/综上/值得注意/意味着） | ≤ 2 | **硬 FAIL** | 换成"那""所以说""我关心的是" |
| 平均句长 | 8-18 字 | **硬 FAIL** | 单句成段的"钉子段"不算违规，但不要通篇都是短句鼓点 |
| 句尾语气词（啊/呢/吧/嘛/呀） | 约 2–5，宁少勿滥 | **仅 WARN** | 不足不再 FAIL；超过约 8 也 WARN。口语主指标是人称与问句，不是语气词 |

### TTS 语气词禁区（硬约束）

以下位置**禁止**加 啊 / 呢 / 吧 / 嘛 / 呀：

1. **专有名词后**（产品名、公司名、人名、型号）
2. **数字 / 评分 / 基准分后**
3. **纯事实陈述句尾**

**允许**出现在：

- 真人会犹豫、缓和、确认的地方（"对吧？""我还是要说一句"）
- **真正问听众的问句**里（"那这个通缩走到哪一步了呢？""那最坏的情况是什么样呢？"）

同一段结尾不要连续堆多个语气词。

### TTS 干净稿规则（行业洞见默认）

- **行业洞见默认直接产出 TTS 干净稿**（流水线走火山 TTS，不另出"人读加语气词版"）。
- 进火山 TTS 前清掉专名 / 数字 / 纯事实句后的尾音；**保留**人称词与真问句。
- 不靠堆语气词硬凑密度；过检时语气词不足只 WARN，人称或问句不足才 FAIL。

### 三条写法（行业洞见特有）

1. **观点由"我"来说**。范例：三五环单口"这是我自己这些年特别关心的一个话题"，面基"我自己感觉你最近聊 ETF 还会聊得比较多"。行业洞见的判断句一律带第一人称："我看这条的重点不在价格，在折旧""我关心的是这笔钱什么时候收得回来"。**禁止整段没有人的判断句连排**，2026-09-28 那篇就是这个问题。
2. **结构不许写进稿子**。本模块要求的倒叙、三层论证、行动层是**写作骨架**，不是台词。稿子里禁止出现"我想用四个问题把这件事讲透""第一个问题""第一层的结论是""落到具体动作，三条建议""最后收个束"这类路标。让数字和事实承担推进，删掉路标以后听众照样跟得上。
3. **金句必须带材料**。这档的标识是锋利判断，但金句不能是空转的对偶。句式菜单里**删掉所有翻案类**（"不是 A，是 B""不在于 A 而在于 B"），改成"数字 + 判断"型："每年的折旧是九千二百亿美元，这个数字不会跟着单价一起掉。"一句金句至少要用上一分钱、一个百分比或一个动作。

**说明（2026-10-13）**：上面 12.6 的语气词是**旧版人读密度**对照，可接受问句/缓和处的「呢/啊/吧」（如"什么样呢？""有意思啊""同感吧"）可以留；**新标准 TTS 稿应明显更低**（软建议约 2–5/千字，宁少勿滥），不要鼓励回到 ≥ 8。学的是人称与真问句，不是语气词密度。

### 四条禁令

1. 不用中文冒号做提示（"所以第一层的结论是：""衡量口径只有一个："），改成句号或"是"字句
2. 不用破折号（`——` 以及任何连接号式破折号）
3. 不写翻案腔（"不是 A，是 B""不在于 A 而在于 B""真正在被瓜分的是"），判断从正面说
4. 不用"这意味着""换句话说""真正的"当洞察路标，也不写"第一层/另一层/更深处"这类结构路标

## 核心约束：一个观点讲到底

### 选题要求

1. **从知乎 AI 大众热点中选取一个问题**作为整期播客的唯一内容；不读取 AI 日报。
2. **选普通用户能感知、愿意讨论的问题**：工作、收入、教育、消费、家庭、医疗、学习和生活方式优先。
3. **先记录知乎热度**：问题浏览量、关注数、回答数、近期高赞和评论表现。热度只证明有人讨论，不证明结论正确。
4. **再用外部论据核验**：至少 3 条可信来源，优先原始论文、官方统计、政府或监管报告，其次高质量媒体和行业报告。不得只用知乎回答里的个人经历当证据。
5. **默认排除两类主题**：Agent 安全与漏洞两类方向不再进入候选池，除非用户明确要求。不要扩大到隐私、监管、合规、诈骗、内容安全、可靠性、模型对齐等其他话题。
6. **行业洞见没有日报钩子**。开头从求职、消费、学习、家庭等现实场景，或从知乎问题中的具体困惑进入。

### 论证深度（这是整期播客的命脉）

**不要列清单，不要走马观花。** 一个观点要拆成多层来论证（具体几层由叙事结构决定，见下方「叙事结构选择菜单」）。

### ⚠️ 论据来源规则（强制，解决“硬凑背景新闻”通病）

**核心原则：知乎热度只说明大众正在讨论，不能代替事实。论据必须通过 DeepSeek Search / Fetch 围绕观点去公开原文核验。行业洞见不读取 AI 日报。**

#### 允许的论据来源

1. **qiaomu-ds-search（主搜索）**：用 DeepSeek 官方 Search 找 3-5 个研究子问题的材料，用 Fetch 读取政策、论文、官方统计和高质量报道正文。
2. **公开原始来源**：政府文件、论文、官方统计、企业原始披露优先；知乎只作需求信号。
3. **DailyAINewsWiki（可选）**：只在某个实体确有历史背景价值时检索 entity/synthesis，不读取 `wiki/sources/daily-*.md`，也不把知识库作为前置条件。
4. **any-search（可选）**：DeepSeek 不可用或需要二次交叉核验时补充。

#### 禁止的行为

- ❌ 引用 AI 日报，或把旧日报里的新闻硬塞进论证
- ❌ 用"五件事连起来是时代信号"这种话术强行关联无关新闻
- ❌ 只用知乎高赞回答或搜索摘要，不读公开原文

#### 自检规则

每引用一条论据时，必须问自己：
- 这条论据和观点有**直接的因果、数据、或逻辑关系**吗？（不是"都是 AI 行业的事"这种宽泛关系）
- 如果删掉这条论据，论证还成立吗？（如果删掉论证反而更清晰，说明这条论据是硬凑的）

## 论证手法（每篇至少用 2 种不同手法）

不要每篇都用"XX说→我解读"一种模式。以下 5 种论证手法，**每篇至少组合使用 2 种**：

| 手法 | 说明 | 示例 |
|------|------|------|
| **名人发言解读** | 引用关键人物的判断，解读其弦外之音 | "Swyx 说了一句话，我翻译一下他在说什么" |
| **数据对比推理** | 把两个看似无关的数据放在一起，得出隐藏结论 | "Anthropic 收入 440 亿，但传统 VC 轮次只占 8%，钱不押注概念了" |
| **历史类比** | 找到过去发生过类似事件的行业/场景，类比推理 | "这像极了 2008 年的智能手机，硬件利润越来越薄，App Store 的分成成了真正的印钞机" |

| 方式 | 说明 | 适用场景 | 示例 |
|------|------|---------|------|
| **大问题** | 抛一个让人停下手上活的问题 | 观点本身指向一个未解之谜或长期争议 | "我一直想一个问题：为什么 Anthropic 的收入能超过 OpenAI？" |

#### 使用规则

1. **每期只选 1 种手法**，开场口播控制在 2-4 句话、不超过 100 字
2. **7 天轮换约束**：近 7 天内用过的手法不得重复，查 `podcast_history.md` 确认上一期行业洞见用的是哪种手法，避开它
3. **手法选择依据**：由 Phase 1.5 母文素材的特点决定（有未解之谜→选大问题；有真实故事→选具体场景；有冲击数据→选反直觉数据；跟生活有关→选日常切入），不要凭个人偏好固定某一种 |

## 金句与钉子段规则

### 金句句式菜单（每篇从中选择 2 种以上，都要带材料）

> **翻案类句式已从菜单里删除**（"不是 A，是 B""并非 A 而是 B""不在于 A 而在于 B""看似 A 实则 B""否定清单型"）。这类句式是模型最容易露馅的地方，全文零容忍。判断从正面说，依据放在旁边。

| 句式 | 说明 | 示例 |
|------|------|------|
| **数字对比型** | 两个数字对撞出一个判断 | "每年的折旧是九千二百亿美元，这个数字不会跟着单价一起掉" |
| **反问型** | 用反问封死退路 | "如果模型能力是唯一壁垒，开源模型早就赢了，为什么没有？" |
| **条件型**（只有X，才能Y） | 给出充要条件 | "只有当你的产品能跟着模型一起变强，你才算上了这辆车" |
| **类比结论型** | 用类比场景收束，类比要写实 | "手机时代赚得最多的那家公司，自己一台手机都不造" |
| **时间压缩型** | 用时间窗口收束 | "你还有六个月的窗口，六个月后这个位置会被别人占掉" |
| **成本还原型** | 把抽象说法还原成钱、时间或人力 | "把供应商换掉要两周，这比模型贵出来的那点钱贵多了" |

### 频率控制

- **翻案类句式全文 0 次**（"不是A，是B"及其所有变形，见上方句式菜单的说明）
- 每个钉子句必须带材料（数字、金额、百分比或具体动作），禁止纯对偶
- 全文钉子段总数：2-3 个（现象层结尾 1 个 + 因果层结尾 1 个 + 终钉 1 个）

## 行动层要求（反空洞）

行动层不要给"关注XX""融入工作流"这种听了等于没听的建议。必须满足以下标准：

### 必须做到

- **给 1-2 个具体行动项**，不超过 2 个（少而精胜过多而空）
- **每个行动项必须包含**：做什么（动词）+ 用什么（具体工具/方法）+ 期望什么效果
- 好的示例：*"这周试试用 GitHub Spec Kit 写一份你产品的 Agent 规范文档，然后让 Claude Code 基于这份规范自动生成测试用例。你看一次能省多少调试时间。"*
- 坏的示例：*"关注 Cursor 和 Claude Code 的最新版本"*（没有动作，没有预期效果）

### 允许的"诚实"

- 如果观点本身没有完美的行动建议，可以坦诚说：*"说实话，对这个问题我现在也没有完美答案。但有一件事是确定的，不做比做错更危险。"*
- 允许用个人经历或朋友的经历代替宏大建议：*"我自己的做法是……不一定对，但至少是个起步。"*

## 去重复约束（防止"三篇听感雷同"）

以下规则是为了确保连续收听多天的听众不会觉得在听同一期节目：

### 禁止重复的元素

- **口头禅控制**：全文同一个短语最多出现 2 次。特别注意以下高频口头禅，每天换着用：
  - "拆干净" / "往下挖" / "把它钉死" / "我翻译一下"
  - 每天最多选 1 个使用，不要全用
- **论证结构去重**：不要每天都用"第一个原因…第二个原因…第三个原因"的编号式论证。可用：
  - 递进式（一层套一层）
  - 对比式（A 路线 vs B 路线）
  - 时间线式（三天前…昨天…今天）
  - 问答式（设问→回答→再设问）
- **过渡句去重**：不要每层都用"好，现象讲完了，现在往下挖"，参见上方过渡方式菜单

### 必须包含的"意外元素"

每篇脚本必须有至少 **1 个**以下元素（让听众有"这个我不知道"的惊喜感）：

- **冷知识**：与主题相关的、大多数人不知道的小事实
- **小故事**：来自 `research_supplement_industry_{date}.md` 的可核验细节，或明确标注的可选知识库背景
- **反直觉数据**：和大众认知相反的数字
- **行业内部术语翻译**：把一个业内人士才知道的术语，用生活化语言解释出来

## 数据核实规则

### 引用数据时的要求

- **具体数字必须来自 `source_brief_{date}.md` 中已核验的 A/B/C 级来源**。如果无法确认来源，删掉数字或降低表述强度。
- **不要在不同段落使用不一致的数据**（如前文写"Claude Opus 4.8"，后文写"Claude Opus 4.7"，先确认哪个是对的）
- **生成时自检**：每引用一个具体数字，确认其来源文件、发布日期、样本口径和限制。待核验的 D 级转引不得进入逐字稿。

### 版本号/模型名谨慎处理

- 模型版本号（如 Claude Opus 4.7 vs 4.8）极容易出错，**不确定时宁可不说版本号，只说"最新版"**
- 融资金额如"350 亿"，确认是美元还是人民币，标注货币单位

## 写作规则

### 段落与节奏

- **每段 1-3 句**，超过 3 句必须拆开
- **钉子段**（单句成段，加粗的判断句）：全文 2-3 个，分布在不同论证层结尾
- 钉子段的情感标签从标签池中轮换，不要每次都用同一个
- 节奏型：信息段（中）→ 钉子段（短）→ 下一层信息段（中）→ 钉子段（短）

### 数字

- 给具体数字，不写模糊词："百分之三十"不是"大幅增长"
- 数字要拆解让人相信："二百五十亿美元，但传统 VC 只占百分之八"
- 对比让数字有画面感："够买五个 Intel"

### 金句

- 金句句式从上方"金句句式菜单"中选择，**翻案类句式一次都不用**
- 金句位置：2-3 个钉子段分布在论证层结尾 + 1 个终钉
- 每句金句至少带一个数字、金额或动作，空转的对偶一律删掉

### 类比

- 来源限制：制造业/日常生活/体育/商业历史，禁止用技术概念解释技术概念
- 每个类比要具体可想象，"像图书馆的索引卡片，能查到书在哪，但卡片本身不告诉你书里写了什么"
- 每篇至少 1 个类比，类比不要和之前脚本中的类比重复

### 禁用词

**以下词语出现一次扣分，出现三次直接判定不合格：**
- 笔者、本文、众所周知、不可否认
- 在当今时代、随着 AI 的发展、接下来、此外、与此同时
- 值得注意的是、值得一提的是、我们需要关注的是
- 这意味着、换句话说、真正的（当洞察路标用时）

**以下结构路标一次都不许出现（骨架不许写进稿子）：**
- 我想用几个问题把这件事讲透、第一个问题、第一层的结论是、另一层、更深处
- 落到具体动作、三条建议、最后收个束
- 中文冒号做提示（"流程是：""衡量口径只有一个："）、破折号（`——`）

### 播客特有规则

- 数字转为口播友好：不写"2970 亿美元"，写"接近 3000 亿美元"
- 不写 emoji、表格、代码块、URL
- 所有事实必须来自 `research_supplement_industry_{date}.md` 和 `source_brief_{date}.md` 中已核验的材料，不编造
- 情感标签必须每段 2-3 个变化
- **语速标签禁令**：`[放慢语速]`、`[加快语速]` 等含"语速/放慢/加快"字样的标签禁用，节奏由标点断句承担
- **数字与单位转换**：日期禁止斜杠（`7/20` ➔ `7月20日`），单位必须汉化（`10px` ➔ `10像素`、`$100` ➔ `100美元`），年份逐位念（`2024年` ➔ `二零二四年`），"2"量词前读"两"（`2亿` ➔ `两亿`）。详见 SKILL.md Phase 2.6C
- **后处理（强制）**：脚本生成后必须经 de-AI-writing 去 AI 味润色 + 情感标签修正 + 数字单位转换，由 SKILL.md Phase 2.6 统一执行
- 语气要有锋芒，但用自嘲和亲历感消解说教味，"我今天特别想聊""我想了很久"而不是"你必须明白"
- **判断句必须有人**：观点用"我看""我关心的是""我的判断是"带出，推演用"你"接住。整段看不到人的判断句连排，按不合格处理

5. 完整读取 `../references/theory-support.md`，检查母文中的主理论、竞争解释和适用边界是否足以支撑脚本。

## ⚠️ 输出格式硬约束（强制，违反即判不合格）

**本提示词上方所有「播客定位」字段（名称/时长/字数范围/格式/受众/铁律）都是给你看的设计参数，不是要写进脚本的内容。** 它们只决定你怎么写，绝不能出现在输出里。

### 脚本必须长这样（精确到第一行）

```
# {话题或人物}:{一句话判断}

[情感描述] 欢迎收听**李自在AI日报**，我是李自在。

[温暖地]开始前说一句，本期结尾有个彩蛋，是我开源的播客流水线，听到最后别错过。

[情感描述] {开头口播，从「大问题/具体场景/反直觉数据/日常切入」选一种} ……
```

**第 1 行**：必须是 H1 标题。人物来源使用「人物:观点」，公共话题使用「话题:判断」。如 `# 年轻人的第一份工作:AI 正在收窄入口` 或 `# 黄仁勋:物理 AI 是下一个万亿美元市场`。
**第 2 行**：必须是空行。
**第 3 行起**：直接进入 `[情感描述]` 品牌口播，中间不能有任何其他内容；品牌口播后必须原样接开场彩蛋提示固定句（含"本期结尾有个彩蛋"与"听到最后别错过"），缺失即不合格。

### 严禁出现在脚本中的元素（出现任意一条即不合格）

| 禁止元素 | 原因 |
|---------|------|
| ❌ Markdown blockquote 引用块（`> xxx`） | 会被 TTS 朗读出来，且不是口播内容 |
| ❌ Markdown 水平分隔线（`---`） | 同上，会被 TTS 错误处理 |
| ❌ 「时长目标：7-10 分钟」「字数范围：2000-3000 字」这类规格说明 | 这是设计参数不是脚本内容 |
| ❌ 「单人深度分析·01fish 观点输出体·三层论证」这类定位描述 | 同上 |
| ❌ YAML front matter（`---\n...`） | 同上 |
| ❌ 任何「## 章节」「### 标签说明」之类的元信息 | 脚本只允许 H1 标题，不允许其他 heading |
| ❌ 把标题以引用形式重复出现在第二行（如 `> 标题：Peter Steinberger:xxx`） | 标题只能出现在第一行 H1，不得再次出现 |

**自检**：把脚本前 6 行单独抽出来看，如果第 3 行不是品牌口播 `[情感描述] 欢迎收听...`，就不合格；品牌口播之后缺开场彩蛋提示固定句，同样不合格。
